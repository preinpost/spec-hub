# Spec Hub 화면 검증 절차

기획·개발·운영이 워크스페이스별 기능명세와 질문·의견·결정을 관리하는 독립 앱이다.
[README](../README.md)의 로컬 실행·로그인을 먼저 따른다.
코드는 `src/{components,pages}`, 웹 API는 `worker/app.ts`에 있다.

## 하위 기능

| 화면 | 경로 | 확인할 기능과 권한 |
|---|---|---|
| 워크스페이스 | `/` | 로그인한 누구나 목록 조회·워크스페이스 생성, 생성자는 관리자 |
| 전체 목록 | `/w/:wk` | 상태 필터, 새 기능, 대·중·소 분류 트리 |
| 명세 상세·편집 | `/features/:key`, `/features/:key/edit` | 본문 저장·미리보기·취소, 의견·수정 제안·질문·결정, 변경 내역·활동 |
| 워크스페이스 설정 | `/w/:wk/settings` | 모두 내 팀 선택, 관리자만 기본 정보·팀·역할·템플릿 변경 |
| AI 연결 | `/me` | MCP 주소 복사, 승인한 앱 조회·연결 끊기 |

초안에서 검토를 요청할 수 있다. 확정은 관리자와 확정권한자만 가능하며 열린 질문이 없어야 한다.
현재 데모에는 공개 범위 설정이 없고 로그인한 사용자는 모든 워크스페이스를 보고 쓸 수 있다.

## 사용자 관점 진입 경로

1. `bash scripts/doctor.sh`로 점검한다.
2. `http://localhost:5185`에서 `Microsoft 계정으로 로그인`을 누른다.
3. 로컬 mock OIDC의 username과 claims를 README 예제로 입력하고 `Sign-in`을 누른다.
4. 워크스페이스 카드를 누른 뒤 전체 목록이나 분류 트리의 기능 이름을 누른다.
5. 모바일에서는 상단 메뉴를 열어 워크스페이스와 기능을 고른다. 링크 이동 후 메뉴가 닫혀야 한다.

## agent-browser 로 조작하기

세션 이름을 붙여 실행하고 조작마다 `snapshot -i`로 최신 ref를 읽는다.
기존 고객사 대시보드의 Masquerade·회원가입 절차는 이 앱에 해당하지 않는다.
로컬 D1과 mock OIDC를 쓰는지 확인하며 원격 DB 명령은 실행하지 않는다.

### 목록·탐색

- 성공: 워크스페이스 카드를 누르고 기능 이름으로 상세에 진입한다. 현재 기능의 상위 분류가 펼쳐지고 선택된 위치가 표시된다.
- 빈 상태: 기능이 없는 상태 필터를 누르면 빈 상태 안내가 보인다. 전체 필터로 돌아오면 원래 기능이 보인다.
- 검색: 사이드바 검색에 기능 이름을 입력하고 Enter를 누른다. 워크스페이스 범위와 결과 링크를 확인한다. 없는 검색어에는 빈 결과 안내가 보인다.
- 유지: 분류를 접고 새로고침한 뒤 접힌 상태가 유지되는지 본다. 기능 상세에서는 해당 기능까지 자동으로 펼쳐진다.
- 반응형: 1440px와 390px에서 목록·상세·편집·설정·AI 연결을 확인한다. `document.documentElement.scrollWidth`가 `innerWidth`를 넘지 않아야 한다.
- 키보드: 모바일 메뉴는 Escape로 닫히고 여는 버튼으로 초점이 돌아와야 한다. 메뉴 안에서는 Tab으로 컨트롤에 접근할 수 있어야 한다.

### 분류 메뉴

- `+ 대분류`는 분류 목록 상단에서 바로 누를 수 있어야 한다.
- 각 분류를 우클릭하거나 분류 옆 `⋯` 버튼을 누르면 같은 메뉴가 열린다. 마우스를 올려도 별도의 조작 버튼 줄이 나타나지 않아야 한다.
- 메뉴에서 하위 분류 추가를 고르면 접힌 부모가 펼쳐지고 이름 입력칸이 보인다. Enter 또는 `저장`으로 저장하고 Escape 또는 `취소`로 취소한다.
- 기능 추가를 고르면 `새 기능` 화면에 해당 분류가 선택되어 있어야 한다. 취소하면 기능이 생성되지 않는다.
- 이름 변경을 저장한 뒤 새로고침하면 바뀐 이름이 남아야 한다. 취소하면 기존 이름을 유지한다.
- 3단계 분류에는 하위 분류를 추가할 수 없고, 기능이나 하위 분류가 있는 분류는 삭제할 수 없다.
- Shift+F10으로 열기, 방향키로 항목 이동, Enter로 실행, Escape로 닫기와 초점 복귀를 확인한다.
- 외부 클릭·스크롤·화면 이동 시 메뉴가 닫히는지 보고, 화면 오른쪽·아래쪽에서 열어도 메뉴가 잘리지 않는지 확인한다.

### 작성·협업

1. 검증용 기능을 만들고 `편집`에서 본문을 입력한다. `미리보기`를 켜 렌더링을 확인하고 `저장`한다.
2. 상세와 새로고침 후 본문을 대조한다(`PUT /api/features/:key`). 목록의 기능 이름·상태도 확인한다.
3. 다시 편집해 내용을 바꾼 뒤 `취소`한다. 상세 본문과 새로고침 후 본문이 바뀌지 않아야 한다.
4. 섹션의 `+ 의견` 또는 `+ 질문`을 열어 입력한 뒤 취소한다. 저장된 의견·질문이 늘어나면 안 된다.
5. 질문을 남기고 검토를 요청한다. 열린 질문 수가 목록·상세에 반영되고 확정 버튼이 비활성인지 확인한다.
6. `답하고 해결`을 눌러 답을 입력하고 `결정하고 해결`한다. 열린 질문은 사라지고 답이 결정 기록에 남아야 한다.
7. `확정`을 눌러 확인 화면에서 취소한다. 검토 중 상태가 유지돼야 한다. 다시 확정하고 변경 내역에서 확정본을 확인한다.
8. 관리자 이외 계정에서도 읽기·의견 작성과 설정 화면을 확인한다. 관리자 전용 수정 컨트롤과 확정 버튼이 표시되지 않아야 한다.

### 오류·설정·AI 연결

- 빈 기능 이름이나 빈 질문에는 생성·제출 버튼이 비활성이다.
- 워크스페이스 목록의 생성 폼에서 기존 키로 만들기를 시도하면 `워크스페이스 키 … 는 이미 있습니다.` 안내가 보이고 기존 워크스페이스가 유지돼야 한다(`POST /api/workspaces` 409).
- 설정에서 내 팀을 바꾸고 새로고침 후 선택이 남는지 확인한다. 끝나면 원래 값으로 복원한다.
- 템플릿 변경 후 `되돌리기`를 누르면 기존 섹션 구성이 유지돼야 한다.
- AI 연결에서 주소 복사를 누르고 `/mcp` 주소가 복사됐는지 확인한다. 연결이 없으면 빈 상태 안내가 보여야 한다.
- 검증용 데이터는 정리한다. 삭제 UI가 없는 기능·워크스페이스를 만들었다면 생성한 데이터만 로컬 D1에서 정리하고 방법을 보고서에 기록한다.

### 메타정보

- 기능 생성·편집 화면의 메타정보 영역에는 선택 항목인 `화면 경로`와 `접근 경로`가 있다.
- `화면 경로`에는 `/invoice` 또는 `/invoice/:id`처럼 제품의 path만 입력한다.
- `접근 경로`에는 `청구 관리 → 청구서 목록 → 상세`처럼 화면에 진입하는 방법을 적는다. 명세 분류와 별개인 자유 텍스트다.
- 도메인이 포함된 URL, `//host`, 공백·역슬래시·query·hash가 포함된 값은 오류 안내가 나와야 한다.
- 올바른 값을 저장하면 명세 상세에서 화면 경로는 코드, 접근 경로는 설명으로 표시되고 새로고침 후에도 유지된다. 현재 기능명세 앱으로 이동하는 링크가 되어서는 안 된다.
- 편집 후 취소하면 기존 메타정보가 유지된다. 각 필드를 비우고 저장하면 해당 값이 삭제된다.
- 기존 기능처럼 값이 없는 경우에도 조회·편집할 수 있어야 한다.
- 메타정보를 확정한 뒤 바꾸면 확정본 이후 변경 안내와 변경 내역에 이전·현재 값이 나타나야 한다.

## 함정

- 기존 대시보드의 `:5173`·`:8000`과 무관한 앱이다. 루트의 backend `.env.local`이 없어도 `--spec-app` 점검으로 검증한다.
- mock OIDC에서 같은 `oid`는 같은 사용자다. 역할이 다른 계정은 `oid`도 바꿔야 한다.
- 확정한 명세를 편집해 저장하면 초안으로 돌아간다. 확정 당시 본문과 템플릿은 확정본에 남는다.
- 템플릿에서 뺀 섹션도 기존 본문이 있으면 이름과 함께 남는다. UI 정리 중 숨기거나 삭제하지 않는다.
- agent-browser 0.39.1에서 `fill ''`은 React 입력 상태를 갱신하지 않는 경우가 있었다. 삭제 검증은 키보드로 마지막 문자를 Backspace 처리하고 저장 버튼 활성화와 API 결과의 null을 함께 확인한다.
