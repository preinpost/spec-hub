# UI 개선 검증 (2026-10-23)

로컬 `http://localhost:5185`와 mock OIDC `:9400`에서 agent-browser로 확인했다.
검증 절차는 [verification.md](verification.md)다.
검증 대상은 공통 UI, 워크스페이스 탐색·목록, 명세 읽기·편집·협업, 분류 메뉴와 메타정보다.

## 사전 점검

```sh
bash scripts/doctor.sh
```

앱 HTTP 200, mock OIDC HTTP 200, 앱 전용 `.dev.vars` 존재, agent-browser 실행을 확인했다.
기존 CONE Watcher backend의 `.env.local`에 의존하지 않는 점검 스크립트를 둔다.
설정값·쿠키·토큰은 보고서에 기록하지 않았다.

## 돌려 본 경로

| 경로 | 결과 | 근거 |

| 로그인 → 워크스페이스 생성 | 성공 | `POST /api/workspaces` 201, UIQA로 이동 |
| 빈 워크스페이스 → 새 기능 | 성공·빈 상태 | 기능이 없다는 안내, 빈 이름에는 생성 버튼 비활성, 생성 후 편집 화면으로 이동 |
| 본문 입력 → 미리보기 → 저장 → 새로고침 | 성공·유지 | 마크다운 제목과 목록 렌더링, `PUT /api/features/UIQA-1` 200, 새로고침 후 본문 유지 |
| 편집 → 본문 변경 → 취소 | 취소 | 저장된 `검증 목적` 본문이 유지되고 취소용 문구가 반영되지 않음 |
| 질문 작성 → 검토 요청 | 성공·제한 | 질문 생성 201, 상태 변경 200, 열린 질문 1개와 확정 버튼 비활성 확인 |
| 질문에 답하고 해결 | 성공 | 열린 질문 0개, 답 `원 미만은 버림 처리합니다.`가 결정 기록에 남음 |
| 확정 화면 → 취소 → 다시 확정 | 취소·성공 | 취소 후 검토 중 유지, 확정 후 1차 확정본과 메모 확인 |
| 확정 후 편집·저장 → 검토 요청 | 성공·권한 | 멤버가 저장하면 초안으로 돌아감, 재검토 상태에서 멤버에게 확정 버튼이 없음 |
| 상태 필터 초안 → 전체 | 빈 상태·복귀 | 초안 0개 안내, 전체로 돌아오면 기능 표시 |
| 검색 → 결과 → 없는 검색어 | 성공·빈 상태 | UIQA 범위 결과 링크, 없는 검색어에는 `찾은 기능이 없습니다.` |
| 기존 키 UIQA로 워크스페이스 생성 | 오류 | `POST /api/workspaces` 409, `워크스페이스 키 UIQA 는 이미 있습니다.` 안내 |
| 설정 → 내 팀 선택 → 새로고침 | 성공·유지 | `PUT /api/workspaces/UIQA/members/me` 204, 선택 안 함 버튼과 팀 선택 유지 |
| 설정 → 템플릿 이름 변경 → 되돌리기 | 취소 | 첫 섹션 이름이 `목적과 배경`으로 복원됨 |
| 멤버의 설정 화면 | 권한 | 기본 정보·팀 추가·역할 변경 컨트롤 없음, 템플릿 입력 비활성 |
| AI 연결 | 표시·빈 상태 | 관리자 기존 연결 표시, 새 멤버는 `연결된 앱이 없습니다.` |
| 분류 우클릭 → 하위 분류 추가 | 성공 | 실제 마우스 오른쪽 버튼으로 메뉴 열기, 부모 자동 펼침, 중·소분류 생성 |
| 분류 ⋯ → 이름 변경 | 성공 | `UI 검증 분류`로 이름이 바뀌고 메뉴 대상 이름도 갱신 |
| 소분류 메뉴 → 기능 추가 → 취소 | 성공·취소 | `분류 선택`에 소분류가 미리 선택됨, 취소 후 기능 수 1개 유지 |
| 소분류·부모 메뉴 제한 | 제한 | 소분류 하위 추가 비활성, 자식이 있는 부모 삭제 비활성 및 사유 표시 |
| Shift+F10 → 방향키·Home → Enter·Escape | 키보드 | 메뉴 첫 항목에 초점, ArrowDown으로 기능 추가 이동, Escape 후 원래 분류로 초점 복귀 |
| 390×600 모바일 탐색 → ⋯ 메뉴 | 반응형 | dialog 안에서 조작 가능, 메뉴 좌표 left 142/top 336/right 382/bottom 592로 화면 안에 표시 |
| 390px 목록·상세·편집·설정·AI 연결 | 반응형 | 모든 화면에서 `scrollWidth=innerWidth=390` |
| 모바일 탐색 → Escape·기능 링크 | 닫힘 | Escape 후 메뉴 열기 버튼으로 초점 복귀, 기능 링크 이동 후 dialog가 닫힘 |
| 분류 메뉴 → 외부 클릭·탐색 스크롤 | 닫힘 | 제목 클릭 후 메뉴 제거, 600px 높이에서 탐색 스크롤 233px 이동 후 메뉴 제거 |
| 메타정보 → 전체 URL 입력 | 오류 | `https://example.com/invoice`에는 오류 안내와 저장 비활성 |
| 메타정보만 입력 → 저장 → 새로고침 | 성공·유지 | `/invoice/:id`와 여러 줄 접근 경로 유지, 본문은 그대로 유지 |
| 메타정보 변경 → 취소 | 취소 | `/cancelled`와 취소용 접근 경로가 반영되지 않고 기존 값 유지 |
| 메타정보 포함 확정 → 경로 수정·삭제 | 이력 | 2차 확정본 이후 변경 안내, 화면 경로의 이전·현재 값, 접근 경로의 기존 값과 현재 미등록을 비교 |
| 메타정보 비우기 → 저장 | 삭제·빈 상태 | API에서 `entryPath: null` 확인, 두 필드 삭제 후 상세에 `메타정보 미등록` 표시 |
| 모바일 새 기능 → 메타정보 입력·생성 | 성공·유지 | UIQA-2 생성 후 편집 입력값 유지, 취소·새로고침 후 상세에도 `/reports/:id`와 접근 경로 표시, 페이지 폭 390px |

UI 수정 전에는 390px에서 페이지가 664px까지 늘어났다. 수정 후에는 각 화면이 390px에 맞는다.
검증 세션에서 `agent-browser errors` 출력은 비어 있었다.

## 검증 범위의 한계

- Microsoft Entra 실계정 대신 로컬 mock OIDC로 로그인했다.
- AI 연결 승인·해제와 MCP OAuth 자체는 이번 UI 변경의 대상이 아니므로 다시 실행하지 않았다.
- 메일·NHN·원격 D1·배포는 호출하지 않았다.
- 구조화된 자동 리뷰는 미추적 PNG 수집 오류로 실행 전에 종료됐다. 위 브라우저 검증과 아래 타입 검사·테스트·빌드 결과를 근거로 남긴다.

pnpm typecheck

길이·경로 유효성, 확정본 보존을 확인한다. 로컬 D1에 `0002_screen_path.sql`을 적용했고 기존 데이터를 보존했다.
문서 수정 후 `git diff --check`, doctor 스크립트의 `bash -n`, 문서 상대 링크 존재 확인도 통과했다.

## 테스트 데이터

UIQA 워크스페이스, UIQA-1·UIQA-2 기능, 그 안의 분류·질문·결정·확정본, 전용 멤버를 생성했다.
기존 WCN 워크스페이스의 명세 데이터는 변경하지 않았다.

검증 후 `wrangler d1 execute DB --local --file …`로 생성한 데이터만 정리했다.
워크스페이스 키 `UIQA`와 이름 `UI 검증 임시 공간`을 함께 조건으로 사용하고,
연관 레코드·기능·분류(깊이 역순)·멤버·팀·워크스페이스 순서로 삭제했다.
전용 사용자 `oid-uiqa-member-20261023`도 다른 워크스페이스 멤버가 아닌 조건으로 삭제했다.
정리 후 워크스페이스는 WCN 하나이며 기능 WCN-1부터 WCN-5까지 5개가 남은 것을 확인했다.
